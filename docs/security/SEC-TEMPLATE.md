# SEC-NNN: <Short, descriptive title>

| Field | Value |
|---|---|
| Record type | Finding, audit, analysis, or security control |
| Date | YYYY-MM-DD |
| Status | Open, mitigated, fixed, accepted, or informational |
| Severity | Critical, high, medium, low, informational, or not applicable |
| Affected components | Paths, contracts, endpoints, or deployments |
| Reporter / reviewer | Name, team, or anonymous |

## Summary

Describe the security property or issue and the conclusion in a few sentences.

## Impact

Explain affected assets, users, prerequisites, and realistic consequences. For an
audit with no vulnerability, state that explicitly and note any residual risk.

## Analysis

Document the relevant code paths, assumptions, and evidence. For a confirmed
finding, include a safe reproduction outline. Keep exploit details private until
the maintainers approve coordinated disclosure.

## Remediation or mitigation

Describe the fix, mitigation, accepted risk, or follow-up work. Include a link to
the fixing change when one exists.

## Verification

List regression tests, audit commands, formal proofs, or operational checks and
their results. For planned verification, identify it as pending.

## References

- Relevant source files, issues, pull requests, advisories, or design documents.
